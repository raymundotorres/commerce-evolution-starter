# Commerce Evolution Project

The final project is an existing e-commerce web application that your team will understand, personalize, and evolve as new business requirements arrive.

The starter is intentionally **not** a blank project and **not** a perfect architecture. It is a small working product whose original design is reasonable for its original requirements.

## Product expectations

By the end of the project, each team will own a visual, usable, persistent web application with a distinct storefront identity. The technical learning goal is not visual polish by itself; the goal is to make and defend sound software-design decisions as the product changes.

## Team and repository

- Teams: **4–5 students**.
- One shared **public GitHub repository** per team, created from the official template.
- Work through branches and pull requests when requested by a milestone.
- Keep the automated test suite and CI healthy throughout the project.

Future change requests are released progressively. Do not design for requirements that have not been given.

## Ground rules

1. **Understand before redesigning.**
2. Preserve existing behavior unless a milestone explicitly changes it.
3. Patterns are tools, not objectives. Do not force them into the project.
4. Automated tests protect behavior while the design evolves.
5. Keep decisions proportional to the actual design pressure.
6. Meaningful AI use must be transparent, critically reviewed, and defensible by the team.
